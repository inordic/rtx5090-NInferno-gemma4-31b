# Night 10 (14 Nov 2026): the drafter's second round, and activation scales for Artemis

Two questions tonight.
- **The drafter.** Night 9's retrained MTP assistant gained on conversation and tool calls, but not on code or maths, which its data barely had ([night 9](2026-11-13-night9-drafter.md)). Does a second round with code, maths and multi-turn agent episodes add those?
- **The scales.** Production's NVFP4 build uses LilaRest's activation scales, and Artemis's activations exceed them in about 100 of 240 places. Does calibrating them for Artemis reduce the error?

**Results**
- **The drafter: faster where the new data was.**
  - Agent episodes: +10% on first turns, +9% on later turns.
  - Code +4.4%, maths +1.8%.
  - English overall +1.5%; conversation and the other languages unchanged.
  - On the greedy prompts, the share of drafts accepted went from 38.6% to 39.4%, identical in every run of each drafter.
  - Not deployed: that needs the owner's OK ([Next](#next)).
- **The scales: almost nothing to gain.**
  - Undoing the clipping lowers the activation error by at most 3.5%, and not on every text.
  - Perplexity on two of the three texts points the other way.
  - Production keeps its scales.
- **Two things went wrong:**
  - A test-server helper's stop command silently did nothing for three hours. Three of the four A/B runs were answered by the wrong drafter. It was found and fixed at 05:06, and the new drafter's runs were redone. The cost: the runs were not interleaved, and the draft-depth sweep was dropped.
  - The 5-bit reference planned for the KL could not load. Production's own artifact with exact activations replaced it.

Production was down from 02:30 to 05:42 CET and came back unchanged: verify OK, follow-up turns at 0.53–0.60 s and 158–159 tok/s, 0 tool-call leaks.

## The drafter

### Data

[`gen10.py`](../bench/runs/night10/gen10.py): public sets and synthetic episodes only, no real conversations.
- **Code:** Magicoder OSS-Instruct problems.
- **Maths:** GSM8K and MATH (levels 2–5) training problems.
- **English chat:** UltraChat prompts that night 9 didn't use.
- **Agent episodes:** synthetic multi-turn sessions of a made-up agent ("Atlas", working for a made-up user, "Sam") in four roles: coder, ops, research and assistant.
  - Each episode has a 2–4K-character system prompt: role, manual, workspace tree, seed code files and memory notes. It comes with 24 tool schemas, so every request starts with 2.4–3K tokens of context.
  - The script simulates the tool results.
  - An episode runs up to six turns. The user sends a follow-up message 60% of the time.

Each prompt was answered by the production server through its normal API, only while it was idle, from 00:09 to 02:29 CET. Half the requests were greedy, the rest at temperature 0.7 or 1.0.
- 2,808 replies:
  - code 673;
  - maths 550;
  - English 243;
  - agent turns 1,342 in 285 episodes.
- About 0.99M tokens written by Artemis, at 118–123 tok/s.
- 402 replies hit the token limit, and 1,132 ended in tool calls.

**Tokenizing** ([`fwd10.py tokenize`](../bench/runs/night10/fwd10.py)):
- Each agent episode is kept as its last turn, which contains every earlier turn. Every assistant span in it is a training span, and the draft steps never run past a span's end.
- 1,748 sequences (3 dropped as too short), 1.84M tokens, 986K draft positions.
- In the agent sequences, 77K of 655K tokens are draft positions. The rest is system prompt, tool results and user turns.

### The target's states and the training

- **Capture:** as in night 9, Artemis was run one layer at a time on production's weights: 40.5 minutes in six passes, 61 GB.
  - **Check:** the pass's greedy token agrees with the served token at 98.50% of 486,073 greedy positions (night 9: 97.9%).
- **Training** ([`train10.py`](../bench/runs/night10/train10.py)):
  - From the night 9 assistant, one epoch.
  - Data: tonight's data (held-out episodes excluded), plus half of night 9's as replay so that conversation isn't forgotten. 2,557 sequences, 1.49M positions.
  - 362 steps of 4,096 positions, learning rate 3e-5 with a cosine decay, 35 minutes.
  - Converted to NVFP4 with production's recipe, to the same size as the current assistant (296,346,628 bytes).

- **The runs were not interleaved.** The night 9 assistant's four runs ran from 03:59 to 05:05 and the night 10 runs from 05:09 to 05:27, all on a warm GPU ([what went wrong](#what-went-wrong)). Acceptance doesn't depend on heat; decode speed can, a little.
- **The held-out agent episodes come from the same synthetic generator as the training episodes:** the same tools and system-prompt template, with different seeds and episodes. Real agent traffic has its own prompts and tools, so +9–10% on agent turns is an upper estimate. A live trial would check it against the server's aggregate acceptance figures.

## Activation scales calibrated for Artemis

NVFP4 scales activations per tensor by `input_scale = amax / (448 × 6)`. Production's scales came with LilaRest's checkpoint. [`calib10.py`](../bench/runs/night10/calib10.py) merged the peak input of every projection from:
- night 9's forward pass;
- tonight's, over all 1.84M tokens except the KL texts' sequences.

108 of 240 projection groups exceed their range, the worst by 14.4× ([`calib.json`](../results/runs/n10/calib.json)). Two variants were built from production's quantized checkpoint, with only the scales changed:
- **V1:** every group whose peak exceeds its range gets the peak plus 25%. No scale is lowered. This raised 184 scales.
- **V2:** halfway, the geometric mean of the old scale and V1's.

The weights stay bit-identical. Rebuilt from the same checkpoint with the same script, production's artifact comes out byte for byte the same apart from its 18-byte id.

### Measurement

[`kl10b.sh`](../bench/runs/night10/kl10b.sh): `ninferno-perplexity`, context 4,096, stride 2,048.
- **Reference:** production's artifact with exact (BF16) activations and BF16 KV, recording its top-32 at every position.
  - V0, V1 and V2 differ only in the scales, so the KL against this reference measures the 4-bit activations alone, which is all the calibration changes.
  - **Sanity check:** V1 with exact activations against the reference gives KL 0.000000 and 100% agreement. Exact activations ignore the scales.
- **Runs:** production's numerics, with 4-bit activations in prefill and FP8 KV.
- **Texts:** Artemis's own held-out replies, with prompts, in the chat format ([`kltext10.py`](../bench/runs/night10/kltext10.py)).

| Mean KL / top-1 agreement / perplexity ratio | V0 (production) | V1 | V2 |
|---|---:|---:|---:|
| Code, maths and English (50,319 tokens) | 0.0295 / 96.09% / 1.006 | 0.0284 / 96.01% / 1.002 | 0.0285 / 96.02% / 1.003 |
| Chat, night 9's held-out (61,531 tokens) | 0.1266 / 90.35% / 1.010 | 0.1274 / 90.70% / 1.035 | 0.1261 / 90.73% / 1.034 |
| Agent episodes (50,346 tokens) | 0.856 / 80.48% / 1.032 | 0.843 / 80.51% / 1.060 | 0.827 / 80.81% / 1.046 |

KL against V0:
- **V2:** −3.3% on code, −0.4% on chat, −3.4% on agent text.
- **V1:** −3.5% on code, +0.6% on chat, −1.5% on agent text.
- **Perplexity on the actual text** favors V1 and V2 on code, but V0 on chat and agent text.

**Verdict:** the clipping looked large, but undoing it gains little. A higher scale clips less but rounds every other activation more coarsely, and the two nearly cancel. Neither measure makes a case for changing production's scales, and the quality checks planned for a winner didn't run. Production keeps LilaRest's scales.

Two observations to follow up:
- **The size of the activation error.** 4-bit prefill activations and FP8 KV together cost a KL of 0.127 on chat. Night 7 measured whole-model errors of 0.13–0.15 for builds of the same kind (NVFP4 weights, the same numerics) against 5-bit references. Those were different models and texts, so the numbers aren't directly comparable. If they hold up on one text, the numerics, not the weight rounding, are most of the gap. FP8 KV and the activations are worth separating, on one text, against a full-model reference.
- **The agent text's numbers are odd.**
  - Its mean KL (0.86) is about 27 times its perplexity change (0.03 per token), and top-1 agreement is only 80%.
  - The text is mostly system prompts, tool schemas and simulated tool results.
  - Something in it may break the measurement, such as special tokens re-read from text or flat distributions over random content.
  - The comparison between V0, V1 and V2 on it is like for like. Its absolute value needs a look before anyone relies on it.

## What went wrong

1. **The test-server stop did nothing.**
   - The runner's helper (`srv10.sh`, a copy of the usual one bound to 127.0.0.1) required the binary's path even to stop a server, and the runner set it only for starts. Every stop failed silently.
   - The first A/B server (night 9 assistant) kept the GPU.
   - The servers for the next three runs failed to start (out of memory). The helper saw a server still running and waited ten minutes each time, then the measurement went to the old server.
   - Its log holds four complete runs of the night 9 assistant, recovered by [`split9.py`](../bench/runs/night10/split9.py). The four runs saw identical prompt sizes in the same order.
   - Found at 05:06 from the empty logs. The stop was fixed (it no longer needs the path) and the leftover server stopped. [`fix10.sh`](../bench/runs/night10/fix10.sh) then ran the two night 10 runs, the KL and the restart, checking that no server remained before each start.
   - The same stop is in the restart path and in the watchdog, so production's return would have failed too. The fix covered both.
   - **Lost:** interleaved runs, the draft-depth sweep (K=5) and the quality checks.
2. **The 5-bit reference could not load.**
   - The public Q5_K_M of Artemis stores some layers' gate and up matrices in different formats (Q8_0 and Q5_K), and the engine needs them as one packed plane.
   - The KL used production's own exact activations instead, which isolates exactly what the calibration changes but not the total error.
3. **A summary name clash.** `heldout10.py`'s "english" line is the English-chat category only, because the aggregate's name clashed with it. `abpair.py` recomputes the English aggregate (every category but Swedish and oasst2) from the per-request rows.
